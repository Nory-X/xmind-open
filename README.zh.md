# XMind Open

[English](README.md) | **中文**

在 Obsidian 的文件浏览器中显示 `.xmind` 文件、内联预览，并交给系统默认程序打开 —— **全程不解析思维导图**。

---

## 它解决什么问题

Obsidian 只在扩展名已注册进视图注册表时，才会在文件浏览器里列出该文件：

```js
isSupportedFile(file) =
  vault.getConfig('showUnsupportedFiles') || viewRegistry.isExtensionRegistered(file.extension);
```

`.xmind` 不在内置扩展名之列，所以你的思维导图在库里是**隐形的** —— 文件浏览器、快速切换、搜索里都找不到。

装一个思维导图插件不一定能解决这个问题。插件可能只注册了**视图**而没有注册**扩展名**，这是两回事。

## 功能

| | |
|---|---|
| **显示** | `.xmind` 出现在文件浏览器中，带 `xmind` 标签 |
| **预览** | 渲染 XMind 存在档案内的导图预览图 |
| **打开** | 把文件交给操作系统，照常用 XMind 打开 |
| **绝不** | 解析、读取或修改思维导图数据 |

## 安装

**手动**

1. 下载或克隆本仓库。
2. 把整个文件夹复制到 `<你的库>/.obsidian/plugins/xmind-open/`。
3. 在 Obsidian 中重新加载插件列表（设置 → 第三方插件），然后启用 **XMind Open**。

仅支持桌面端（Windows / macOS / Linux）。移动端无法打开外部程序。

## 使用

点击任意 `.xmind` 文件。会打开一个标签页，显示导图预览和一个「用系统默认程序打开」按钮。

也可以在文件浏览器中右键点击文件，选择「用系统默认程序打开」。

## 设置

| 设置项 | 默认 | 说明 |
|---|---|---|
| **点击后自动用系统程序打开** | 关 | 关闭时只显示预览、等你点击；开启后打开文件立即唤起外部程序 |
| **显示缩略图** | 开 | 渲染存在档案内的预览图 |
| **XMind 程序路径** | *(空)* | 留空即使用系统文件关联。仅当关联缺失、或被别的程序抢占时才需要填写 |

### 关于程序路径

默认情况下插件**从不寻找 XMind**。它把**文件**交给操作系统，由系统按自己的文件关联解析 `.xmind` —— 所以无论 XMind 装在哪里都能工作，也无需任何配置。

这个设计只有一种失效场景：系统里没有任何程序关联 `.xmind`，或者关联被别的程序抢走。此时打开不会产生有意义的结果。针对这种情况，设置里可以填一个明确的路径，而**自动检测**按钮会尝试帮你找到它：

1. 从注册表读取当前的 `.xmind` 关联（`HKCR\.xmind` → `shell\open\command`），然后
2. 依次检查常见安装位置（`%ProgramFiles%`、`%ProgramFiles(x86)%`、`%LOCALAPPDATA%` 等）。

检测出的路径必须**真实存在**才会被采纳，所以注册表里的陈旧条目不会被误用。

当路径**确实**被配置时它优先，且启动失败会直接报出原因而不是静默回退 —— 否则一个坏配置看起来会像成功。

## 预览是怎么来的

`.xmind` 文件本质是一个 ZIP 档案，XMind 会把导图的渲染图存在 `Thumbnails/thumbnail.png`。因此显示它只需要**从 ZIP 里读出一个条目**，而不需要理解 XMind 的文档格式。思维导图数据（`content.json`）从未被打开。

插件自带一个小型 ZIP 读取器（定位 EOCD、遍历中央目录、解压单个 deflate 条目），而没有捆绑第三方库 —— 因为插件本身是单文件、无构建步骤。

一切都安静降级。缺少预览条目、档案损坏、或图片过大，都只意味着**这次没有图** —— 文件仍能正常打开。

## 权限与系统访问

为了完成工作，插件会触及库之外的少量东西。这里逐条列出，而不是藏进设置里。

| 行为 | 原因 |
|---|---|
| 读取你所打开的 `.xmind` 里的 `Thumbnails/thumbnail.png` | 那是 XMind 自己存进去的预览图。档案里的其他内容一概不读 |
| 解析该文件的绝对路径 | 操作系统需要一个真实路径才能打开它 |
| 启动与 `.xmind` 关联的应用程序 | 这是插件的主要动作 —— 用 XMind 打开你的思维导图 |
| **可选地**启动一个你指定的可执行文件 | 仅当你填写了 **XMind 程序路径** 时。留空则插件不会运行任何未经你指定的东西 |

插件不遍历目录，不读取库内或库外的其他文件，也不向任何地方上传数据。

## 隐私

- 从不发起网络请求。
- 不向你的库写入任何内容。
- 对你打开的每个 `.xmind` 文件，只读取一个条目（`Thumbnails/thumbnail.png`），解码结果**仅缓存在内存中**，以路径与修改时间为键。

## 语言

界面跟随 Obsidian 自身的语言设置：中文界面显示中文，其余显示英文。

## 开发

插件是单个 CommonJS 文件，无构建步骤。`main.js` 是 Obsidian 加载的唯一入口。

离线测试套件位于 `tests/`。它用桩化的 `obsidian` 模块和 jsdom 运行真实的插件代码，因此无需安装 Obsidian：

```bash
# 88 条断言：扩展名注册、视图、打开链、缩略图提取、自定义路径、国际化
node tests/run-tests.js

# 20 个变异体：每个故意破坏一处行为，套件必须失败 —— 否则对应用例什么都证明不了
node tests/mutate.js

# 用真实的 .xmind 文件交叉校验 ZIP 读取器，与 Python 的 zipfile 对比字节
node tests/verify-thumbnail.js /path/to/file.xmind
```
